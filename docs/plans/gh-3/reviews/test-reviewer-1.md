## Findings
### 1. Nothing proves `SettingsPage` saves through the hook that updates the session and the directory — major
**Where:** `SettingsPage.test.tsx` (*saving the name*), `App.test.tsx` · **Checked:** sketched correct (23/23), then replaced `useUpdateDisplayName` in the sketch with a page-local `useMutation` that only does `setQueryData(['profile','me'])` — still **23/23 green**. `useProfile.test.ts` proves the hook; the page tests assert only the PATCH body, the field error and "Saved".
Req 5 and *Where the rules meet* 3 say the success of a rename on this page updates the session profile and the directory, so the sidebar and the renamer's own message authors never disagree. The only test that reaches the page's save with a real session is the journey, which looks at the sidebar and not at the author of Alan's own messages, and which cannot run before the code-writer's e2e. A page that bypasses the hook ships Req 5 wrong with every Vitest layer green.
**Settles it:** in `SettingsPage.test.tsx`, one test like `useProfile.test.ts`'s setup — `session.restore()` through `auth.me/workspaces/refresh` stubs, seed `['workspace-members', ws]` with the user's row, `auth.updateMe` accepting the rename, render the page, save "Ada L", then assert `session.snapshot()` profile `displayName` and the cached directory row are "Ada L" (and Grace's untouched). It fails the page-local mutation above and passes the correct sketch.
